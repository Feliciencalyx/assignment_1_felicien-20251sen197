Project summary

This project implements a relational database for Sunrise Supermarket. It stores customers, products, orders, and individual products included in each order. The database is populated with sample data and analyzed using SQL JOINs, a Common Table Expression (CTE), and window functions. The analysis identifies customer activity, product purchases, customer spending, revenue growth, purchasing rank, order sequence, and the time between repeat purchases.

Business scenario

Sunrise Supermarket sells products to customers who place orders containing one or more items. Management needs reliable information about its customers, the products they purchase, and how revenue changes over time. The database and analytical queries in this project help management identify high-value customers, inactive customers, popular purchases, repeat-purchase behavior, and cumulative sales performance.

JOIN queries

1. Orders with customer details

SELECT
    o.order_id,
    c.customer_name,
    c.city,
    TO_CHAR(o.order_date, 'DD-MON-YYYY') AS order_date
FROM orders o
INNER JOIN customers c
    ON o.customer_id = c.customer_id
ORDER BY o.order_date, o.order_id;

Explanation: This INNER JOIN combines orders and customers through customer_id. It returns only orders having a matching customer and displays the order ID, customer name, city, and order date.

Result: The query returned all 15 orders with their corresponding customer information.

Business interpretation: Management can identify who placed each order and compare purchasing activity across cities such as Kigali, Musanze, Huye, and Rubavu.



2. Order items with product details

SELECT
    oi.order_item_id,
    oi.order_id,
    p.product_name,
    p.category,
    p.price,
    oi.quantity,
    (p.price * oi.quantity) AS item_total
FROM order_items oi
INNER JOIN products p
    ON oi.product_id = p.product_id
ORDER BY oi.order_id, oi.order_item_id;

Explanation: This query joins order_items to products using product_id. The calculated item_total multiplies the unit price by the quantity purchased.

Result: The query returned 30 order items with their product information and calculated line totals.

Business interpretation: Management can see what was purchased, the product category, the quantity sold, and the revenue generated by each order item.



3. All customers and any orders they placed

SELECT
    c.customer_id,
    c.customer_name,
    c.city,
    o.order_id,
    TO_CHAR(o.order_date, 'DD-MON-YYYY') AS order_date
FROM customers c
LEFT JOIN orders o
    ON c.customer_id = o.customer_id
ORDER BY c.customer_id, o.order_date;

Explanation: The LEFT JOIN returns every customer, including customers without a matching order. Order columns are NULL for a customer who has never ordered.

Result: The query returned 16 rows: 15 order records and one row for Samuel Habimana with no order.

Business interpretation: Management can distinguish active customers from customers who have not bought anything. Customers without orders can be targeted with first-purchase promotions.

CTE query: customers above average spending

WITH customer_totals AS (
    SELECT
        c.customer_id,
        c.customer_name,
        NVL(SUM(oi.quantity * p.price), 0) AS total_spent
    FROM customers c
    LEFT JOIN orders o
        ON c.customer_id = o.customer_id
    LEFT JOIN order_items oi
        ON o.order_id = oi.order_id
    LEFT JOIN products p
        ON oi.product_id = p.product_id
    GROUP BY
        c.customer_id,
        c.customer_name
)
SELECT
    customer_id,
    customer_name,
    total_spent,
    ROUND((SELECT AVG(total_spent) FROM customer_totals), 2)
        AS average_spend
FROM customer_totals
WHERE total_spent > (
    SELECT AVG(total_spent)
    FROM customer_totals
)
ORDER BY total_spent DESC;

Explanation: The customer_totals CTE calculates each customer's total spending as quantity × price. LEFT JOINs retain customers with no orders, and NVL converts their missing total to zero. The outer query calculates average spending and returns only customers whose totals exceed that average.

Result: Total supermarket revenue was RWF 231,600. The average across six customers was RWF 38,600. Alice Uwase spent RWF 68,000, Diane Ingabire spent RWF 49,600, and Eric Mugisha spent RWF 44,800, placing all three above average.

Business interpretation: These above-average customers are high-value customers. Management could reward them through loyalty benefits, personalized discounts, or early access to promotions.



Window-function queries

1. Rank customers by total spending

WITH customer_totals AS (
    SELECT
        c.customer_id,
        c.customer_name,
        NVL(SUM(oi.quantity * p.price), 0) AS total_spent
    FROM customers c
    LEFT JOIN orders o ON c.customer_id = o.customer_id
    LEFT JOIN order_items oi ON o.order_id = oi.order_id
    LEFT JOIN products p ON oi.product_id = p.product_id
    GROUP BY c.customer_id, c.customer_name
)
SELECT
    customer_id,
    customer_name,
    total_spent,
    RANK() OVER (ORDER BY total_spent DESC) AS spending_rank
FROM customer_totals
ORDER BY spending_rank;

Explanation: RANK() assigns a spending position to each customer from highest to lowest. Customers with equal totals would receive the same rank.

Business interpretation: The ranking identifies the most valuable customers. Alice Uwase ranks first with RWF 68,000 in total spending.



2. Number each customer's orders

SELECT
    o.customer_id,
    c.customer_name,
    o.order_id,
    TO_CHAR(o.order_date, 'DD-MON-YYYY') AS order_date,
    ROW_NUMBER() OVER (
        PARTITION BY o.customer_id
        ORDER BY o.order_date, o.order_id
    ) AS customer_order_number
FROM orders o
INNER JOIN customers c
    ON o.customer_id = c.customer_id
ORDER BY o.customer_id, customer_order_number;

Explanation: ROW_NUMBER() numbers orders chronologically. PARTITION BY restarts the numbering at 1 for each customer.

Business interpretation: Management can distinguish a customer's first purchase from later purchases and study repeat-order behavior.



3. Running total of revenue over time

WITH daily_revenue AS (
    SELECT
        o.order_date,
        SUM(oi.quantity * p.price) AS revenue_for_date
    FROM orders o
    INNER JOIN order_items oi
        ON o.order_id = oi.order_id
    INNER JOIN products p
        ON oi.product_id = p.product_id
    GROUP BY o.order_date
)
SELECT
    TO_CHAR(order_date, 'DD-MON-YYYY') AS order_date,
    revenue_for_date,
    SUM(revenue_for_date) OVER (
        ORDER BY order_date
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS running_revenue
FROM daily_revenue
ORDER BY order_date;

Explanation: The CTE first calculates revenue for each date. The windowed SUM() accumulates the daily values from the first date through the current date.

Business interpretation: The running total reveals how sales revenue grows over time. The final cumulative revenue is RWF 231,600.



4. Days between consecutive orders

WITH order_history AS (
    SELECT
        o.customer_id,
        c.customer_name,
        o.order_id,
        o.order_date,
        LAG(o.order_date) OVER (
            PARTITION BY o.customer_id
            ORDER BY o.order_date, o.order_id
        ) AS previous_order_date
    FROM orders o
    INNER JOIN customers c
        ON o.customer_id = c.customer_id
)
SELECT
    customer_id,
    customer_name,
    order_id,
    TO_CHAR(previous_order_date, 'DD-MON-YYYY') AS previous_order_date,
    TO_CHAR(order_date, 'DD-MON-YYYY') AS current_order_date,
    order_date - previous_order_date AS days_between_orders
FROM order_history
WHERE previous_order_date IS NOT NULL
ORDER BY customer_id, order_date;

Explanation: LAG() retrieves the previous order date for each customer. Oracle date subtraction then calculates the number of days between the previous and current order. First orders are excluded because they have no earlier order.

Business interpretation: The result shows how often customers return. Shorter gaps indicate more frequent purchasing and stronger customer engagement.

Challenges encountered and resolutions

ORA-65096 while creating the user

Challenge: The sunrise_user account was initially created while connected to CDB$ROOT, causing ORA-65096 because a local username cannot be created in the root container without the C## prefix.

Resolution: The session was changed to the FREEPDB1 pluggable database before creating the local user:

ALTER SESSION SET CONTAINER = FREEPDB1;

ORA-02291 while inserting orders

Challenge: Orders were initially inserted before their customer parent records existed. This violated the FK_ORDERS_CUSTOMER foreign key.

Resolution: Customer records were inserted and verified first, followed by orders and then order items. The correct insertion order is customers, products, orders, and order items.

SP2-0734 during INSERT ALL

Challenge: Blank lines caused SQLPlus to terminate an unfinished INSERT ALL command. Later INTO lines were interpreted as independent SQLPlus commands.

Resolution: The order-item records were inserted using individual single-line INSERT statements, avoiding blank-line parsing problems.

Ensuring customers without orders were included

Challenge: INNER JOINs exclude customers without related orders.

Resolution: LEFT JOIN was used when all customers were required. NVL converted a missing spending total to zero in the CTE and ranking queries.
